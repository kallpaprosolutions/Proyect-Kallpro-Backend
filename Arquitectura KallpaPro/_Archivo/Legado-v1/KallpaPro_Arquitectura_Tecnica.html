Resumen Ejecutivo
Visión estratégica y propuesta de valor de la plataforma unificada

El problema actual

KallpaPro opera hoy con dos sistemas paralelos desconectados: KallpaPro Interactive (UX enriquecida, asistente IA, flujos de solicitud y reportes) y KallpaPro Secure (login por roles, gestión de usuarios, seguridad avanzada). Esta fragmentación crea fricciones de UX, duplicación de lógica de negocio, mantenimiento doble del código base, y riesgo de inconsistencia de datos entre los dos sistemas.

La unificación no es solo técnica: es estratégica. La plataforma combinada transforma a KallpaPro de "dos herramientas" a un verdadero SaaS logístico enterprise competitivo con Nowports, Flexport y los players regionales emergentes en LATAM.

La solución propuesta

Una plataforma única denominada LOGIFI™ Platform v2.0 construida sobre arquitectura híbrida (monolito modular + microservicios selectivos), desplegada en la nube con capacidades de multi-tenancy, IA contextual con Claude, rastreo GPS en tiempo real, y gestión granular de usuarios y dominios por tenant.

🔗
Core
Unificación total
Una sola codebase, un solo estado de autenticación, un solo flujo de datos. Elimina la duplicación y los bugs por inconsistencia entre sistemas.
🤖

Claude integrado en cada módulo con contexto completo de la plataforma. No un chatbot genérico: un analista logístico que conoce cada pedido, proveedor y ruta.
📡
Real-time
Tiempo real nativo
WebSockets + Server-Sent Events para tracking GPS, alertas, y actualizaciones de dashboard. Arquitectura event-driven con Apache Kafka para escalar sin límite.

Aislamiento de datos por tenant, dominios personalizados configurables por admin, y gestión granular de roles y permisos (RBAC + ABAC).
🔒

🔌

Framework de integración
API REST + GraphQL pública documentada. Webhooks para eventos. Conectores nativos para GPS (Geotab/Mapon), ERPs (SAP, Odoo), y facturación SRI Ecuador.

Arquitectura del Sistema
Diseño modular escalable — Híbrido: monolito modular + microservicios selectivos

Decisión arquitectónica: ¿Por qué híbrido?

Los microservicios puros son prematuros para el estado actual de KallpaPro (complejidad operacional sin beneficio real). Un monolito puro limita la escala independiente de módulos críticos como IA y tracking. La arquitectura híbrida (Modular Monolith + Microservices selectivos) permite comenzar con velocidad de desarrollo y escalar los módulos de mayor demanda de forma independiente.

Monolito modular
  • Core business logic (pedidos, proveedores, usuarios)
  • API Gateway unificado
  • Base de datos principal PostgreSQL
  • Autenticación y autorización
  • Módulo de reportes y POV
Microservicios selectivos
  • Tracking Service: GPS, WebSockets, alta frecuencia
  • AI Service: Claude API proxy, rate limiting, caching
  • Notification Service: WhatsApp, email, push
  • Integration Service: ERP connectors, GPS APIs, SRI

Diseño enterprise que prioriza la eficiencia operacional sobre la estética

Principios de diseño

Information density
Los usuarios operativos necesitan ver más datos en menos espacio. No un diseño minimalista vacío. Dashboard denso pero legible, similar a Bloomberg Terminal o Linear.
Acción a 2 clics
Cualquier acción crítica (crear pedido, asignar proveedor, confirmar entrega) debe completarse en máximo 2 clics desde cualquier pantalla.
IA siempre accesible
El panel de IA es persistente y contextual. Cambia su comportamiento según el módulo activo. No hay que navegar a él: responde al estado actual.
Mobile-first para conductores
La app del conductor (PWA) está diseñada para uso con guantes, pantallas con brillo solar, y conexión intermitente. Offline-first con sincronización diferida.

Modelo de Seguridad
Defensa en profundidad — múltiples capas de protección para datos logísticos críticos
🔐
Auth
Autenticación multi-factor
// Flujo de autenticación LOGIFI™ 1. Email + Password (bcrypt 12 rounds) 2. MFA: TOTP (Google Auth) | SMS OTP → Obligatorio para Admin y Gerente → Opcional para Viewer/Conductor 3. JWT Access Token: 15 minutos JWT Refresh Token: 7 días (httpOnly) 4. Session binding: IP + User-Agent hash 5. Suspicious login → email alert + block 6. Max 5 failed attempts → lockout 15min
🛡️
Encryption
Cifrado en reposo y tránsito
  • En tránsito: TLS 1.3 obligatorio. HTTP Strict Transport Security (HSTS). Certificate pinning en app móvil.
  • En reposo: AES-256-GCM para datos PII. Claves manejadas por AWS KMS. Rotación automática cada 90 días.
  • Archivos (PODs): Cloudflare R2 con cifrado side-by-side. URLs firmadas con expiración de 1 hora.
  • API Keys: HashiCorp Vault. Nunca en código o env vars. Rotación automática.

Estrategia de Escalabilidad
Del primer tenant a 500 empresas sin refactoring arquitectural

Horizontal scaling

Kubernetes con Horizontal Pod Autoscaler (HPA). Los pods del Core API escalan automáticamente cuando el CPU supera 70% o la latencia media supera 200ms. Sin cambios en código.

Min replicas: 2 pods
Max replicas: 20 pods
Scale up: CPU >70%
Scale down: CPU <30% / 5min

Database scaling

PostgreSQL con Read Replicas para queries de reportes y analytics. Sharding por tenant_id cuando se superan 1M operaciones/mes. Connection pooling con PgBouncer.

Write: 1 primary
Read: 2 replicas
Max connections: 500
Query cache: Redis (TTL 5min)

WebSocket scaling

Socket.io con Redis adapter para compartir estado entre instancias. Un cliente puede conectarse a cualquier pod y recibir los eventos de sus operaciones correctamente.

Max connections/pod: 10K
Redis pub/sub adapter
Sticky sessions: deshabilitado
Heartbeat: 25 segundos

Riesgos y Mitigaciones
Análisis honesto de los principales riesgos técnicos, operativos y de negocio

🔴 Riesgos técnicos

Alto
Corte de API de Claude / Anthropic
Mitigación: Fallback a respuestas basadas en reglas predefinidas. Cache de las 100 consultas más frecuentes en Redis. SLA de Anthropic: 99.9%. Monitoreo activo con alertas a 99.5%.
Alto
Pérdida de datos GPS en tiempo real
Mitigación: Kafka con replicación factor-3. GPS device con buffer local de 1h. Si cae el servidor, el device guarda localmente y sincroniza al reconectarse.
Medio
Cobertura de internet en zonas remotas (minería)
Mitigación: Driver app en modo offline-first. Datos sincronizados cuando hay conexión. GPS con SIM card dual para fallback a operadora secundaria.
Medio
Migración de datos desde sistemas actuales
Mitigación: Scripts de migración con validación automática. Periodo de doble operación (ambos sistemas en paralelo 30 días). Rollback plan documentado.

🟡 Riesgos de negocio y adopción

Alto
Resistencia al cambio por parte de usuarios operativos
Mitigación: Onboarding guiado de 3 sesiones. Videos tutoriales por rol. Periodo de co-existencia con sistema anterior. Capacitación a los coordinadores que multiplican el conocimiento.
Medio
Dependencia de proveedores GPS (Geotab/Mapon)
Mitigación: Abstraction layer que permite cambiar de proveedor GPS sin modificar la plataforma. Contratos con cláusulas de exportabilidad de datos.
Medio
Brecha de seguridad y exposición de datos de clientes
Mitigación: Penetration testing trimestral. Bug bounty program. Seguro cibernético. Plan de respuesta a incidentes documentado. Notificación a usuarios en <72h (LOPDP).

Roadmap de Implementación
4 fases de 36 meses — de MVP unificado a plataforma SaaS enterprise regional
FASE 1 — Semanas 1–12
Unificación y MVP (Quick Wins)
Fusión de KallpaPro Interactive y KallpaPro Secure en una única codebase. Objetivo: tener un sistema funcional para los clientes actuales sin fricciones.
Migrar autenticación segura al sistema interactivo
Unificar gestión de usuarios con dominios personalizados
Claude API integrado en todos los módulos
WebSockets para GPS en tiempo real
Despliegue en AWS (us-east-1)
CI/CD pipeline GitHub Actions
Monitoring: Grafana + Sentry
KPI de éxito: Plataforma unificada en producción con los clientes actuales migrando sin pérdida de datos.
FASE 2 — Meses 4–9
Producto SaaS completo (Operación inicial)
Lanzamiento como producto SaaS con planes de precios, facturación automática, y las integraciones más críticas del ecosistema ecuatoriano.
Billing automático (Stripe / Kushki Ecuador)
Integración Geotab + Mapon GPS production
WhatsApp Business API para alertas
Módulo de procurement completo (RFQ → OC)
App móvil conductor (React Native)
Integración SRI facturación electrónica
Multi-tenancy completa con dominios custom
Apache Kafka en producción
KPI de éxito: 10+ tenants pagando, MRR $8,000+, NPS >50, uptime 99.5%.
FASE 3 — Meses 10–24
Escalamiento y diferenciación
La plataforma ya es estable. Ahora se construyen las ventajas competitivas difíciles de copiar: IA avanzada, marketplace B2B de productos, y expansión regional.
RAG system: IA aprende del historial de cada tenant
Predicción de ETA con ML (XGBoost)
Optimización de rutas (Vehicle Routing Problem)
Conectores ERP: Odoo + SAP B1
API pública documentada (OpenAPI 3.1)
Marketplace B2B capa inicial (insumos)
Expansión: Colombia + Perú
SSO enterprise (SAML 2.0)
KPI de éxito: 50+ tenants, MRR $42,000+, 2 países, primera ronda de inversión cerrada.
FASE 4 — Meses 25–36
Plataforma regional enterprise
KallpaPro se convierte en la capa de software logístico del comercio B2B latinoamericano. El marketplace de productos usa la logística como canal de distribución nativo.
Marketplace B2B completo (products + logistics)
Servicios financieros (factoring logístico)
IoT: sensores de temperatura + telemetría avanzada
Data lake: benchmarks del mercado logístico LATAM
White-label para operadores logísticos
Expansión: México + Chile
KPI de éxito: 200+ tenants, ARR $5M+, GMV >$30M/mes coordinados en plataforma, referenciados como el "Nowports del transporte terrestre LATAM".
